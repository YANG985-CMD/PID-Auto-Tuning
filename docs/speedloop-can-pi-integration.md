# 现有 CAN 接口已接入真实 SpeedLoop PI

日期：2026-10-11。此前已完成 CAN 物理收发、诊断回读及心跳失联的板上验证，本阶段复用这些结果，没有重新测试接线或物理链路。

## 这次完成的代码

原 CAN 端点使用同步 `begin/apply/snapshot` hooks；原 SpeedLoop 则在 1ms 速度任务中运行 PI，并在更快的 ADC 回调中持续更新模糊增益。新增 `motor_td3_speedloop_can`，让同一 CAN 端点的参数处理在**实际生成模型的 PI 边界**执行。

- CAN RX 仍使用现有分帧、CRC、会话和序号检查，只排队。
- reset 时暂缓 BEGIN/GAINS；HELLO、STOP 和过期拒绝照常处理。
- PI 边界先完成上一输入积分，再调用端点。受保护动作直接提交完整 Kp/Ki，调整积分状态；原端点核对实际参数后才确认应用。
- BEGIN 的板级启动 hook 只在基准增益真正提交后调用。它必须由运行固件实现经过验证的启动门控，不得再写 PI 参数。
- 设备时钟、CAN 到达时刻、控制边界和应用反馈统一使用同一 DWT 时间轴；端点与 PI 的中断访问串行化。
- 完整私有副本接入现有 G431 HAL RX 队列与已使用过的单帧 Tx 事件核验，取消原例程的占位 CAN 发送和 UART 接收/DMA 遥测冲突，保留 CRC/会话协议。
- 已连接正式 `0x621` 反馈编码入口，反馈使用实际参数和边界应用时间。缺失温度等非有限观测仍拒绝编码为训练数据；锁定身份保留原始诊断输出。

## 实际执行的接入检查

主机使用现有 Python CAN 编码器、C 协议端点、用户的真实 `FOC_Model.c` 和真实模糊控制器；物理输出与传感器由明确的**软件测试 hooks**代替。

| 测试中的事件 | 设备模拟时间 | 实际动作记录 |
|---|---:|---|
| BEGIN 参数进入 RX 队列 | 100µs | 尚未提交 |
| 基准 PI 在真实速度任务提交 | 1100µs | 内部 wire 序号 1 |
| GAINS 进入 RX 队列 | 1100µs | 反馈仍是旧的动作序号 0 |
| 新 Kp/Ki 提交并反馈 | 2100µs | 动作序号 1，Kp≈0.0038、Ki≈0.0017；应用时间与 PI 记录一致 |

上述是合成观测下的代码执行记录，不是实机电机响应。10 项接入检查通过，覆盖实际调度/应用时间、积分连续性、reset 推迟、期限、STOP、重放、传感器故障、缺失温度和零能力身份拒绝。

现有 CAN 运行器的 19 项回归也通过，包含新增的 reset 就绪状态检查；之前的串口/桥接、诊断身份和固定镜像检查继续由 CI 运行。核心 PI 的 20 项检查、原模型 10 项检查及 2000 步模糊基准对照保持通过。

完整 Cortex-M4 私有副本 **49 个单元编译链接成功，BIN 为 48012 B**；text/data/bss 为 `47908/104/8224 B`。原工程源树未变。公开仓库只保存自有接入代码与摘要，厂家工程和 BIN/HEX 保存在本地。

## 板上状态与剩余工作

本阶段没有连接设备、烧录或复测物理 CAN。板上仍保留此前的热诊断固件，新复核镜像为 `g431-speedloop-pi-can-review-v1`：相桥启动入口移除，CAN 能力仍为 0，START/GAINS 仍被锁定保护拒绝。

共享 CAN 源码已经更新，旧热诊断工具会拒绝其历史构建与当前源码指纹不一致的组合。固定镜像、源码、符号和能力校验保持不变；本次只调整软件测试的合成镜像 fixture，继续验证版本不匹配会被拒绝。不能用旧入口下载新 PI/CAN 镜像。

复核副本不是运行版：锁定适配层会关闭 MOE，因此也关闭原 CH4 ADC 触发。这里验证的是完整代码接入、真实 PI 数值和编译图，尚未运行这份固件或验证它的采样时序。既有诊断版的独立看门狗验收仍保留，本副本没有自动继承为已验证的运动看门狗。

当前剩余集中在**同一份运行固件中的启动门控、持续采样、独立进展/停机保护和热能力配置，再接 Actor**。CAN 物理通信已经通过，不再列为待重新验证的前置项目；新的运行镜像仍须按其实际功能验证。保持未知温度/热限值，不通过设置能力位或复制软件 fixture 限值开放运动。
