# 2026-10-12：新增六轮实机采集与响应窗口修正

## 本轮做了什么

用户确认 24V 接通、空载、轴停止、人员远离、CAN 与 STLink 连接后，Codex 执行一批六轮有界采集：baseline / Ki+ / baseline / Ki− / Ki+ / Ki−。每轮最多 3 秒，间隔至少 30 秒，整批预算 18 秒。沿用完整镜像已核验的 v5 固件，没有烧录或应用 Actor。

六轮全部通过：故障 0，STOP 确认，六路输出关闭，核心暂停，然后释放 CAN。名义峰值电流最大 1.076660 A，采样峰速最大 1784.440 rpm。温度仍未知，电流换算未独立标定；SKILL.md 和普通温度门保持不变。

这次两轮 baseline 的实际增益全程固定为 Kp=0.003389、Ki=0.00144，修复后的显式模式不再夹带 Kp 探测。Ki 探测四轮的 Kp 均固定，Ki 只使用已有的 ±0.000036 局部幅度。完整实际回读、原始报文和 Hall 边沿已公开。

新增 58 个原审计口径的短窗口，累计 41 个独立会话、369 个短窗口。

## 修正实际动作与保活的区别

原处理对每条 GAINS 命令都等待新应用时间。零变化命令只是维持已回读的参数，等待保活 ACK 会漏掉这段增益实际上已知的响应。

新处理保留两个不同时间：

- 新增益：响应必须晚于实际应用时间。
- 保持已有增益：源快照已经确认相同 Kp/Ki，可从源快照之后观察；原始命令的应用时间仍保留，没有提前伪造 ACK。

同一增益的保活窗口可以合并。不同增益、未知阶段、故障、时间/序号异常或不同 boot 会话不能合并。每个原窗口只归属一个合并组或拒绝记录，后续响应采样点不重复计数。

第 4 轮有一条命令没有足够后续点构成单独窗口；原始遥测序号连续。只有当中间每个实测点的参数仍相同，才可跨过这段已知保持区间。实际观察到的应用序号另外记录，不能把缺少单独窗口等同于丢帧，也不能忽略不同参数的中间动作。

## 两种窗口标准分别记录

| 窗口标准 | 有效窗口 | 训练 | 验证 | 训练结果 |
|---|---:|---:|---:|---|
| 严格：至少 4 点、实际观察跨度 60 ms | 141 | 106 | 35 | 不足 128，不创建 Agent、不更新权重 |
| 探索：至少 3 点、实际观察跨度 40 ms | 193 | 146 | 47 | 仅做离线敏感性实验，禁止部署准入 |

训练/验证按完整 boot 会话隔离。原有验证会话保持固定，第 41 个会话在看分数前被预留为新增验证会话。探索标准是独立的数据窗口敏感性实验，不是严格标准通过；没有复制、插值或增加日志行来凑够样本。128 个训练窗口的门槛保持不变。

奖励使用实际响应点之间的时间权重。原目标状态仍是十个工程特征，动作仍是实际 Kp/Ki 变化。折扣明确为每个合并决策一步 gamma=0.99；窗口时长并不固定，因此不能解释成每 100 ms 的时间折扣，也不能用旧策略的更新节奏直接套用新模型。

## MATLAB 实际训练

探索数据进入 MATLAB R2024b 原生 TD3 回放池，启用行为克隆正则 2.5、随机种子 7/17/27，每个种子 80 步，共 240 步。验证数据不进入回放池；Actor 和两个 Critic 权重都有实际变化。

| 种子 | 验证状态上的平均 Kp 动作 | 平均 Ki 动作 |
|---|---:|---:|
| 7 | 0.009046 | 0.002668 |
| 17 | -0.015459 | 0.001431 |
| 27 | -0.012697 | -0.016680 |

这些是归一化变化建议，不是直接 Kp/Ki 数值，也不是速度误差。三个种子的 Kp 方向仍不一致。三个新候选均未通过准入，没有对应检查点的实机性能数据，性能字段保持 null，部署许可为 false。

另外产生 540 条已证明 RunStage 状态的训练后离线回放建议，保存实际 Kp/Ki、Actor 建议、映射后的候选增益和模型 SHA。所有 hardware_writeback 为 false。这些建议不是运动期间的实时预测；本轮没有给新网络做 45 ms 实时延迟测试。

本轮完成了实机采集与训练后候选生成。基准 PI 保持不变，Ki 当前基准仍为 0.00144。严格数据还缺 22 个训练窗口；本批 18 秒预算已经结束，不自动追加运动。

## 验证与复现

- Python：20 项窗口因果关系、回读、间隙、跨会话、重复点和候选准入检查通过。
- MATLAB：6 项经验哈希、掩码、重复响应、验证隔离、折扣和严格门禁检查通过。
- 3 个 Actor、6 个 Critic 的 JSON 权重与 MATLAB 往返一致。
- 原始遥测和实际应用反馈保留；发布 SHA 清单采用 Git 的 UTF-8 LF 字节，原本地字节哈希另存。

主要入口：

- scripts/speedloop_response_windows.py：从审计结果和原始遥测生成两个窗口标准。
- matlab/validateSpeedLoopResponseReplay.m：独立检查实际动作、归一化、哈希、去重和划分。
- matlab/trainSpeedLoopResponseTD3.m：严格经验不足直接退出；实验经验训练后只形成候选。
- matlab/replaySpeedLoopResponseSuggestions.m：训练后回放，绝不写板。
- scripts/select_td3_candidate.py：探索窗口标记、检查点不匹配或性能证据不足均不能获得部署许可。

入口路径相对于 motor-td3-serial-tuning skill。临时输出使用用户指定目录；正式记录见 [response-window-20261012](../examples/speedloop-v5-real-20261012/response-window-20261012)。

算法依据延续 [TD3 原论文](https://proceedings.mlr.press/v80/fujimoto18a.html) 与 [TD3+BC 原论文](https://arxiv.org/abs/2106.06860)。这些依据不能替代本电机的性能比较和保护验收。
