## Codex 本轮完成的工作

Codex 核对采样与保护接口，实现原始 ADC 的单位转换和时序检查，运行故障测试，分析失败原因，创建禁止运动的工程副本并编译链接。Codex 还检查最终符号中没有 PWM 启动、FOC step 或模糊 PI 执行入口。

这为后续 TD3 实验准备可审计的保护输入。Codex 仍可管理 MATLAB 训练、分析独立性能评估并导出 Actor；本轮没有生成真实训练经验或部署 TD3 闭环策略。

## 接入层做了什么

1. 使用每相独立校准记录，将 A=ADC1 JDR1、B=ADC2 JDR1、C=ADC1 JDR2 转成安培。要求校准已验证且包含实测范围；标称数字不能解除门槛。
2. 检查有效标志、ADC rails/校准范围、连续源序号、实际采样时间和处理时延。丢一个样本即故障，不用后续数据补齐旧窗口。
3. 对每个三相样本分别平方和累计；校准后的绝对采样峰值达到门槛立即禁能，不等 RMS 窗口结束。
4. 形成均方电流、最低绝对速度和“任一采样间隔内使能”的完整窗口，交给三相热预算。停机样本不清预算，重复初始化不能清除预算或首个故障。
5. 新采样停止时，独立检查采样期限。正常且新鲜的完整窗口只产生热模块的许可，不启用 PWM，也不批准其他保护或 TD3 参数。

源码入口为 `motor_td3_thermal_feed.c/.h`。驱动器仍须证明三相转换完整、无 overrun、PWM 采样窗口有效和时钟可信；软件检查不能单独证明这些硬件事实。所有热模块调用须由单一保护任务串行拥有，实际并发与最坏执行时间尚未测量。

## 完整工程为什么仍不能作为热保护固件使用

新身份为 `g431-speedloop-heat-audit-v1`。`motor_td3_speedloop_thermal.c` 中只读校准、热限值与启动热 seed 均为缺失状态，**初始化预期故障是 `TD3_FEED_CALIBRATION`**。本轮用真实接线层的主机测试证明这一拒绝行为；没有从 MCU 读取这个故障。

接线层保留原来的标称电流显示，未将它作为经标定的热保护输入。原有约 100Hz 软件 ADC 是顺序转换，SysTick 时钟为 1ms；这不是 10kHz FOC 电流/RMS 采样。原编译版本仍移除全部 PWM 启动和 FOC 执行入口，能力位为 0；缺失温度继续为 NaN。

SysTick 对热层只维护 64 位时钟，前台负责热检查；原有输出禁能、ADC/前台/心跳监督与 IWDG 保留。热故障只在独立模块状态中记录，CAN v1 尚未携带这些字段。这样可以检查代码接线和禁止启动行为，但不能声称已经具备真实热保护或替代了协议中的温度要求。

旧下载器仍只接受原来审核的固定镜像；新镜像的身份和哈希不同，不能用旧入口直接烧录。原看门狗版重建核验通过，其二进制 SHA256 仍为 `ea6bb46181092ed415cdcc804ceccac6c14fdedfa8861d3797f1f6fa9c41e54d`。

新镜像 SHA256 为 `1b324fe500349cd26b14feed70ecb6b0bd835d98245fb93ddfa202b568ea5cb4`。链接统计：text=42080 B、data=20 B、bss=8520 B；符合芯片映射仅说明静态布局可链接，栈峰值、运行时内存和执行时间还未验收。

## 后续缺口

- 实测三相电流增益、标定覆盖范围与实际过流触发；目前固定 24V 电源与现有仪器尚未形成受控标定夹具。
- 当前电机连续相 RMS 电流、过载/低速/堵转依据，以及 MOSFET/功率板独立热边界。
- 经验证的初始热状态、保守持久化/丢电恢复或人工冷机流程。
- 实际 PWM 触发的完整三相采样与热层接入，实际相桥活动回读，保护任务并发和实时预算。
- 带版本的保护状态遥测、实体急停、运动停机时限及有界基准试验。
