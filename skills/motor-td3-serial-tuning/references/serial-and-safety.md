# 串口、保护与经验审计

## 设备与主机协议

JustFloat 可继续用于人工看曲线；仅靠固定顺序 float 和尾标记不能证明机器训练数据完整、命令已生效或状态新鲜。TD3 使用带长度、版本、类型、序号、设备时间和 CRC 的帧，或经同等验证的现有协议。遥测、命令、确认可采用不同帧类型。不要把日志字段当成已实现的固件协议。

遥测至少能提供：

- 协议/固件版本、启动会话 ID、序号、设备时间；
- 速度给定、反馈、可验证的电流量、母线电压；
- PI 积分输出和当前实际 Kp/Ki，或为不可测积分状态定义的历史替代与验证依据；
- 驱动使能状态、故障码、保护事件、传感器有效性、最近已应用命令序号；
- 温度或经验证的替代保护、通信丢帧/过载计数。

参数命令白名单只包含明确授权的速度 PI 参数、预先批准的试验给定、状态查询与安全停止。启动有明确的状态机；学习动作不直接包含 PWM、d/q 电压、保护阈值、急停复位或 Flash 擦写。

`SET_GAINS` 应原子携带 Kp、Ki、会话 ID、命令序号、有效期和校验，返回拒绝原因或在实际应用之后返回参数与应用时刻。不能逐个改 Kp、Ki 形成未经验证的过渡组合。阻止旧会话命令、重放、重复动作、过期动作和队列堆积。

MCU 校验有限数值、单位、上下限、单次变化及允许状态，再在控制周期边界更新。确认 KI 是连续积分增益还是已经乘以采样时间的离散增益。无扰切换应按实际 PI 实现维护积分输出连续并保留抗饱和，不能简单清零或错误倍乘积分状态。

遥测限速、DMA 缓冲区生命周期、发送忙计数和接收边界检查在控制实时预算内验证。不要在高频电流中断里做阻塞发送或学习计算。

## 三级保护

1. **驱动器/硬件**：现有过流关断、急停、供电/机械限制。依据故障类型定义停止方式；有些负载自由滑行或再生制动各有风险，不把单一停止命令当成普适安全。
2. **MCU**：独立过流/超速/电压/温度/传感器保护，数值与参数域校验、动作租约、命令失联超时与故障锁存。不依赖 Codex 或训练程序作实时判断。
3. **主机监督器**：每帧检查健康、序号、时效与保护余量，拒绝不合格动作；对训练器无进展、CPU 堵塞、端口断开和异常退出执行终止流程。

心跳与动作租约绑定健康检查和有限实验预算，不是只要进程存活就允许电机永远运转。独立 MCU 超时必须经过断线和主机终止的实际验证。

```text
DISARMED → 版本/健康握手 → 验证基准 → SHADOW
                  ↓ 实机已授权且保护经验证
            BOUNDED_TRIAL → STOPPED → 评估
                  ↓ 故障/过期/超预算
               FAULT_LATCHED（不自动重启）
```

停止流程应同时停止策略发布和学习会话，尽力发送已验证停止命令并等待确认，记录结果；finally 中发送 STOP 是补充措施。断线时依靠 MCU/硬件保护，并把停机是否确认写清。

主机和固件的限制必须同时存在，不能以 skill 提示词替代固件保护。超过授权预算就停止；新的候选网络不自动扩大边界。

## 会话配置

`assets/session-profile.example.json` 为正式会话配置模板，`mode=plan`，未配置数值为 null。运行 `check-profile --live` 检查针对实机的完整性，不应修改模板里的开关来伪造验证。

配置中的 `verified` 项必须关联验证记录或源码和试验依据。`fixed_policy_evaluation_verified` 表示固定策略评估流程已验证可用；每个待发布模型仍需单独评估，不能据此自动上线。规划/经验检查器允许以 `verified_alternative` 记录经过验证的替代保护依据；**当前实机运行器、v1 遥测和 guard 尚未接通替代模式，运行器会明确拒绝它**。已有三相热预算的离线模块和接入合同见 [sensorless-thermal.md](sensorless-thermal.md)；不能为了通过校验填一个假的温度。

配置完整性不等于硬件安全认证、授权、闭环稳定或某次试验已完成。

## JSONL 经验记录格式 v1

每行一个对象；原始帧及无法形成有效经验的事件另行保存，不伪造经验来凑数据。

| 字段 | 定义 |
|---|---|
| schema_version | 1 |
| run_id, episode_id | 同一实验与回合标识 |
| step | 回合内从 0 开始递增 |
| profile_id, firmware_id, protocol_id, policy_version | 可追溯版本 |
| state, next_state | 与配置 `state_fields` 完全匹配的有限数值对象；保留原始单位，训练器另外进行归一化 |
| action_proposed, action_applied | 两个包含 `kp, ki` 的物理参数对象 |
| command_seq, applied_command_seq | 下发序号、MCU 确认的序号，一致才能归因 |
| next_applied_command_seq | 下一状态期间的应用序号；正常窗口必须不变 |
| t_state_us, t_apply_us, t_next_us | 展开回绕后的同一设备单调时间；状态 ≤ 应用 < 下一状态 |
| telemetry_seq_start, telemetry_seq_end | 窗口起止遥测序号，必须递增 |
| max_frame_gap_ms | 窗口内最大帧间隔，不能只看起止序号 |
| reward | 可重算、有限的窗口奖励 |
| terminated, truncated | 布尔值；本工作流不允许两者同时为真 |
| stop_reason | none, safety_fault, episode_limit, operator_stop, link_loss, command_unconfirmed, clock_reset |
| safety_intervention | 响应窗结束前发生安全投影、拒绝、回退或停止接管时为 true；仅在窗末确认的故障终止由 stop_reason 标明 |
| learner_eligible | 是否作为普通 TD3 学习输入；未知动作/未知终点为 false |

扩展字段可以保存奖励分项、原始帧文件、约束峰值、温度、CRC 计数、探索噪声和拒绝原因。审计器检查必需字段、有限性、时序/回合/命令对应和配置边界，不证明原始硬件数据没有被伪造。

`learner_eligible=true` 的正常经验必须有已确认动作、时间对齐、连续的状态与正常终点。物理增益必须在配置局部域内，动作变化满足配置。当前审计器对 `safety_intervention=true` 采用严格排除，不能跨过被排除的窗口继续拼接学习链；如需训练带已知安全映射的环境，先升级数据契约与审计，不能跳过拒绝。

下发浮点参数前按协议的实际表示量化（例如 float32），`action_proposed` 记录量化后真正发送的数值，`action_applied` 记录对应回读。先在设备与主机之间约定表示，再比较；禁止把数值表示差异当成设备自行放宽安全范围。

可确认的 `safety_fault` 使用 `terminated=true` 且奖励包含配置的故障惩罚；窗口可提前终止，但必须仍有已确认的动作和真实终点。仅因正常回合时限停止时用 `truncated=true`。失联、缺应用确认、时钟复位时不能把未知终点当成正常下一状态；这些事件 `learner_eligible=false`。

旁路预测保存在单独的 `shadow_proposal` 日志；`action_applied` 始终由实际控制器回读产生。

## 必要验证

先做没有硬件副作用的故障注入：NaN/Inf、超域、单位错误、过期动作、旧序号、确认丢失、CRC 错误、遥测断流、设备复位、缓冲溢出、训练器卡住、主机终止。确认全部触发预期的拒绝/退出，不自动重启。

实机验证独立停止与保护必须单独有授权和可控制的测试条件。日志审计、模拟器测试和 skill 校验都不能替代它。
