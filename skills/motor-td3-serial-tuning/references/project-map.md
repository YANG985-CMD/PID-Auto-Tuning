# MCU 工程接入检查清单

从目标工程实际编译引用的源文件建立接入点映射。不要凭目录名判断哪一份是正在使用的固件，也不要把示例协议等同于设备已经支持的协议。

## 需要定位的模块

| 模块 | 要确认的信息 |
|---|---|
| 串口接收与命令解析 | 缓冲边界、帧结束条件、严格数值解析、白名单、版本/序号/校验 |
| 速度 PI | Kp/Ki 的实际变量、单位、积分状态、抗饱和与输出限幅 |
| 参数更新 | 参数唯一所有者、控制周期边界、原子写入与生效确认 |
| 遥测 | 真正上报的状态、设备时间、应用序号、故障与测量有效性 |
| 调度与中断 | 速度/电流任务周期、遥测发送预算、DMA 缓冲生命周期 |
| 故障处理 | 独立过流、超速、失联、动作有效期与急停行为 |
| 仿真模型 | 电机/逆变器参数、离散 PI 与实际固件的对应关系 |

在常见 STM32 工程中，可以从 `Core/Src/main.c`、应用控制模块和 UART 模块入手；具体路径以编译工程为准。Simulink 生成代码须同时检查模型和生成接口，避免下次生成覆盖手工接入代码。

## 串口解析风险

如果现有示例使用 `P1/P2/P3/P4` 和 `!` 结束符，先核对每个命令的实际语义。支持 Kp/Ki 写入不代表已经支持在线探索。

- `atof` 不提供完整的解析错误信息；需要严格解析，并拒绝尾随垃圾、NaN、Inf 和超范围值。
- 超长帧应丢弃到明确帧边界，避免尾部被解析成新命令。
- 参数接收与控制器应用是不同事件，应用确认须发生在实际写入之后。
- 两个增益需要原子应用，不能让控制器经历未经验证的中间组合。

## 遥测真实性

检查器使用的字段必须来自真实遥测。结构体中存在 Torque、Power、Iq 或温度变量，不表示其已经正确计算并上报。估计量标明来源，缺失量不能以零值伪装成正常测量。

JustFloat 曲线可以保留供人工观察；机器经验记录仍需可验证的时序、应用序号和数据有效性。

## 参数唯一所有者

若模糊 PI、自适应模块或其他任务会持续写入增益，需要定义控制模式及唯一参数所有者，否则 TD3 的参数可能被覆盖。保留现有控制器作比较基准，不丢弃用户已有实现。

MCU 电流环、速度环和电脑串口调参的周期分别确认。高频控制任务的采样周期不能直接作为电脑 TD3 决策周期。

配置模板中的 PI 数值只用于演示配置与审计器。真正的基准、局部范围和更新限制从目标设备验证取得。
