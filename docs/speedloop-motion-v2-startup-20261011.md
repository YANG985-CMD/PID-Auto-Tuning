# SpeedLoop v2 启动问题与修复

## 实际故障

v1 完成编译、烧录和完整回读，但通电后的 HELLO 没有回包。没有发送 BEGIN 或 GAINS。停机检查确认三相通道为 0。

定位到两项启动错误：

1. CAN 端点初始化要求每个计划转速的绝对值严格小于保护上限。计划含 1800/2000 rpm，而上限是 1800 rpm，初始化直接失败。v2 只允许已观察过的 1000 rpm 基线。
2. TIM1 的 CH4 ADC 触发依赖 MOE。清除 MOE 虽关闭相桥，也切断了控制采样。v2 按已运行的基线程序保留 CH4/MOE，同时清除六路相桥使能位，并将六个功率引脚保持 GPIO 低电平。

MOE 为 1 不代表此时相桥已使能；判断还需要 CCER 与功率引脚模式。调试器暂停也不等于电机停机。

## 修复内容

- 在 ADC 中断启动前初始化模型、PI 绑定和 CAN 端点。
- 每次 C 启动清零后、进入 main 前设置独立会话标识；初始化消费后清零。使用明确的 SYSRESETREQ 和同一次调试连接完成准备，检查断点与 PC 后才能写标识。
- 以一次 CCER 写入开启三相通道，取消逐路 HAL PWM Start。
- ADC 采样和母线电压均记录真实采样时间；ADC 忙或转换失败时不刷新母线时间。
- 首轮最长 3 秒。缺失温度只在明确开启的专用试验编解码模式中保留为未知，其他非有限数值仍拒绝；标准编解码和 skill 的温度保护要求保持原样。

## 已取得的证据

在 24V 物理断开、USB/STLink 连接的条件下烧录 v2，完整回读 49132 字节，SHA-256 一致。运行约 0.5 秒后 ADC 计数 4970、零点采样完成、端点就绪、故障为 0；三相 CCER 位为 0，六个功率引脚为 GPIO 低电平。

[正式启动记录](../examples/controller-comparison-20261011/speedloop-pi-motion-v2-startup.json) 包含镜像哈希和板上状态。私有厂家源文件、完整固件及原始调试文件没有发布。

新增检查直接编译本次私有副本里的实际适配器和实际生成模型，以主机 HAL 替身验证正常/失败启动、标识消费、等待零点时保留采样、采样无效拒绝启动、过期母线拒绝启动及故障禁能。它们不能替代真实相桥、比较器或运动失联测试。

## 后续实机步骤

v2 的真实 HELLO 已回包，身份和六项能力一致，仍没有发送 BEGIN/GAINS。完整状态检查拒绝该会话，随后 RAM 回读确认保护时间故障 9；STOP 关闭 MOE、三相通道保持关闭，先暂停核心再释放 CAN。[正式实测记录](../examples/controller-comparison-20261011/speedloop-pi-motion-v2-handshake.json) 保留此次失败。

ADC 中断优先级为 0，高于 SysTick。SysTick 原先先取时间、再调用保护逻辑；两步之间 ADC 可以抢占并发布更晚时间，使 SysTick 的较早时间被判为倒退。v3 对时间捕获和保护更新一起加临界区。新增抢占检查直接在实际适配器上复现：v2 失败，v3 通过。v3 完整遥测周期为 20 ms。

v3 也补上端点尚未就绪时的主循环失联禁能：超时标志置位后直接关闭硬件输出。26 项禁止运动适配器回归和 10 项运动启动检查均通过。

## v3 真实复测

v3 已断电烧录并完整回读一致，镜像 49148 字节，SHA-256 `7128a27aad687c31a3bc26c2734eb6ea3d79cc96922addf0b2f6319d25fd3c93`。断电启动采样计数 4966，端点就绪且故障为 0。

接通 24V 后观察到控制器重新启动，准备标识已清零。本次按用户此前授权保留 24V 的要求，对这份准确哈希的已核验镜像启用专用会话准备例外：复位前验证 MOE 关闭、三相使能为 0、六路功率引脚为 GPIO 低电平；复位后核验相桥关闭，在 C 初始化完成后的 main 断点设置新标识。没有重新擦写 Flash 或发送 BEGIN。例外入口拒绝其他哈希的镜像。

随后收到 116 组完整状态，序号与时间连续，故障均为 0。名义母线 24.215～24.550 V，名义电流 0～0.04395 A；没有温度测量，字段保持未知。STOP 后 MOE 清零、三相通道关闭，先暂停核心再释放 CAN。[实测摘要](../examples/controller-comparison-20261011/speedloop-pi-motion-v3-handshake.json) 与 [实际状态帧](../examples/controller-comparison-20261011/speedloop-pi-motion-v3-disabled-telemetry.jsonl) 已保存。

运动测试前仍需验证修正版完整采集、进展监督、独立看门狗与停机链路，随后才能采集实际 Kp/Ki 动作对应的速度响应。静态数据不用于伪造 TD3 经验，候选训练与四方法实机比较尚未完成。
