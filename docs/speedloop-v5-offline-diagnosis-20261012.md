# 2026-10-12：实机数据问题定位与 TD3 离线对照

本轮使用已经取得的电机实物数据，未连接硬件、启动电机或写 Flash。Codex 审计动作与响应、配置并调用 MATLAB 训练、检查 Actor/Critic 和准入结果、发布可复核记录。**12 个新候选均未通过筛选，当前保持基准 PI，部署许可为 false。**

## 1. 实际数据覆盖

35 个独立 boot 会话得到 311 个实际动作窗口；整轮有故障、序号断裂、应用回读缺失、重复会话或缺少原始 Hall RunStage 证明的记录不进入本次经验池。按完整会话固定划分：228 个训练窗口、83 个验证窗口。所有配置采用同一划分、种子 7/17/27 和每个种子 80 步更新，没有将验证窗口加入回放池。

## 2. 已修复的问题

### 基准标签与实际行为不一致

两批 Ki 采集的第 1、3 轮标为 baseline，但实际 Kp 从 0.003389 变为 0.00352456；这些轮次包含 4% Kp 探测，不能用作固定 PI 的性能对照。保留原始文件和历史标签，在 coverage-analysis.json 中增加修正注释。

后续采集必须显式选择 gain-mode：baseline、kp_probe 或 ki_probe。baseline 全程固定两项增益；Ki 探测中 Kp 固定。冲突的模式在连接硬件前被拒绝。

### 旧策略实机结果被用于评价新网络

旧准入脚本把原始 Actor 的 A/B 表用于不同随机种子的新候选，并固定输出 rejected。这不能给新候选赋予实机性能结论。

新脚本要求候选 checkpoint SHA-256 和动作掩码都与实机评估一致。无匹配结果时 physical_metrics 为 null，不能继承其他网络的误差、电流或峰速。满足重复试验条件的测试用例可得到 repeat_evaluation_passed，普通部署仍需未训练工况、温度门和独立电流标定。

旧 Actor SHA-256 为 2d9516d757ad8e9784da9171afe48f5dc60f809666639084c691bbc10b23efab，实际应用仅 Kp、Ki 固定。它的三对 A/B 结果仍有效：RMSE 144.734 → 149.636 rpm，峰值名义电流 1.040039 → 1.054688 A，峰速 1670.556 → 1726.111 rpm，未通过。新候选没有对应的实机 A/B 数据。

### 动作掩码必须进入网络与噪声

Ki 屏蔽现在位于 Actor 内部，同时屏蔽目标策略噪声和探索噪声。不能在预测后才把 Ki 改成零，更不能把已经实际施加的非零 Ki 经验改标成零动作。掩码与实际动作冲突时直接拒绝经验。

新增数据包含 Ki 正负动作，因此本次双输出离线对照使用 [1,1]。这不批准 Ki 上板应用；当前实际控制器的 Ki 仍为 0.00144。

## 3. 本次 MATLAB 对照

使用 MATLAB R2024b 原生 rlTD3Agent/trainFromData：比较原奖励与增强奖励，并分别启用或关闭原生行为克隆正则，权重参数为 2.5。四组采用相同网络、输入缩放、数据划分、种子和更新步数，合计 960 步；Actor 和双 Critic 权重均实际更新。

| 配置 | 种子 7 的平均 Kp 动作 | 种子 17 | 种子 27 | 筛选 |
|---|---:|---:|---:|---|
| 原奖励 TD3 | 0.01200 | -0.01359 | -0.01485 | 未通过 |
| 增强奖励 TD3 | 0.01205 | -0.01356 | -0.01483 | 未通过 |
| 原奖励 TD3 + BC | 0.00976 | -0.01283 | -0.01528 | 未通过 |
| 增强奖励 TD3 + BC | 0.00983 | -0.01280 | -0.01521 | 未通过 |

表中动作是归一化增益变化建议，不是直接 Kp 值或电机误差。三个种子的方向仍不一致；BC 没有消除这项筛选问题。本次预算和窄数据覆盖下，不能声明算法已收敛或优于基准 PI。

ablation.csv 和 validation-seed-*.csv 公开 Actor 建议、实际动作、Q 值及诊断指标。Q 值、行为动作 MSE 和当前网络 Bellman 残差用于检查数值行为，**均不是新策略的实机 RMSE**。残差采用当前 Critic 和确定性下一 Actor，不伪称目标网络训练损失。

12 个 Actor、24 个 Critic 权重以 JSON 发布，与 MATLAB 权重往返一致。完整检查点保存在本地 models/offline-study-20261012，未上传二进制 MAT。没有生成最终 MCU Actor C 文件。

## 4. 为什么目前没有稳定改善

审计直接证明：数据只来自 1000 rpm，Ki 调节次数少，动作窗口大多是保活而且响应短；新速度和饱和惩罚没有产生信号。33 次试验的峰速发生在首个训练源状态之前，训练奖励与完整启动表现不能等同。

据此推断，当前 Critic 对状态相关增益效果的识别依据不足；单纯增加日志行数或增大奖励权重难以补足信息。种子方向不一致是诊断现象，本身不能证明具体物理因果，也不能代替实机性能验证。

后续重点是：保留阶段证明，按实际动作组织更长且可观测的响应窗口，区分调节与保活，统一评价阶段，再扩展独立目标转速/负载。下一版可先在离线重放中检查窗口组织和延迟；本轮不自动增加实机预算或放宽准入条件。

## 6. 论文依据

[Fujimoto 与 Gu，A Minimalist Approach to Offline Reinforcement Learning，NeurIPS 2021](https://arxiv.org/abs/2106.06860) 提出在 TD3 策略更新中加入行为克隆与数据归一化，用于固定数据的离线学习。本项目采用其约束思路；沿用已有工程输入尺度，未声称完全复现论文的全部设置。

[MathWorks 官方行为克隆选项说明](https://www.mathworks.com/help/reinforcement-learning/ref/rl.option.rlbehaviorcloningregularizeroptions.html) 给出原生 BatchDataRegularizerOptions 接入方式。已在本机 R2024b 中构造并训练通过；权重参数参与标准 Actor 损失缩放，不能把数值越大简单解释成克隆约束越强。

基础 TD3 依据：[Addressing Function Approximation Error in Actor-Critic Methods](https://proceedings.mlr.press/v80/fujimoto18a.html)。论文思路与本项目性能结论分别记录。
