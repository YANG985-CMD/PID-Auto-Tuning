# 示例程序的温度、过流保护与参数边界核对

2026-10-11，Codex 按用户提供的手册、原理图和本地示例检查现有实现。本次只读资料与源码，没有连接调试器或 CAN、复位、烧录、改参数或启动电机。用户原工程未修改。

## 结论

| 项目 | 已找到的依据 | 仍未证明的部分 |
|---|---|---|
| 温度采集 | 当前 PID / 模糊 PI 应用未实现；所核对原理图未发现电机或 MOSFET 的 NTC/温度传感器电路；手册 MCSDK 配置取消 Temperature Sensing | 不能把缺失值当成正常温度；没有测温不代表没有热风险 |
| 过流封波 | 当前 PID 工程已有 PB1 → COMP1 → TIM1 Break，DAC3 CH1 设为 3000，禁止自动恢复输出 | 该板实际触发电流、响应延迟、输出电平、故障锁存和三相正负电流覆盖均未验收 |
| PI 参数边界 | 模糊规则表给出有限增益集合；当前 PI 输出及 NNSMC 叠加后均限制在 ±3 A | 规则范围不是闭环稳定性证明，也不是已批准的 TD3 探索范围 |
| 示例一致性 | 手册、原理图、解压工程与压缩包分别核对 | 同名章节或压缩包不能保证是相同程序版本 |

因此，后续接入应复用已有电流采样、比较器及 PI 限幅，再补验证和故障管理。温度应记录为硬件/应用能力缺失，不能描述成已经存在、只差接线的软件功能。

## 1. 温度：现有示例没有采集实现

PID 工程 `Core/Src/adc.c`：

| 转换组 | 通道与位置 | 用途 |
|---|---|---|
| ADC1 常规组 | CH11，第 76 行 | 电位器 |
| ADC2 常规组 | CH1，第 175 行 | 母线电压 |
| ADC1 注入组 | CH3 / CH12，第 88 / 107 行 | A / C 相电流 |
| ADC2 注入组 | CH3，第 156 行 | B 相电流 |

当前应用未配置 `ADC_CHANNEL_TEMPSENSOR`，也未发现 NTC 换算或过温停机逻辑。PID 工程 `main.c` 第 383 行的 `HallTemp` 是定时器捕获周期，第 367 行的 `tempData` 是发送缓冲区；它们都不是温度。芯片库包含温度相关宏，也不能证明应用正在测量电机或功率器件温度。

手册 PDF 第 28 页的 MCSDK 配置明确取消温度传感器，并取消该界面的过流保护选项、说明由软件保护。这是该 MCSDK 示例的配置，不能用它推断后面自建 FOC 示例也关闭了 TIM1 Break。

手册 PDF 第 10 页和测试手册第 3 页要求关注 MOSFET 温度，并提示输入电流持续超过 4 A 时加装散热器；这是使用说明，没有提供温度遥测或热停机实现，也不能把 4 A 当成当前设备的许可运行边界。两份资料的母线输入范围亦不同，不据此自动扩大现有 24 V 会话范围。

**后续取舍：**可接入外部测温，或设计并验证适用于该电机、功率板和工况的限时/冷却/热预算方案。单纯规定短时间并不能证明热保护有效。当前 TD3 运行器仍要求有效温度及其边界，尚未实现替代热保护模式；本次没有删除校验、伪造温度或改用 MCU 内部温度冒充 MOSFET/绕组温度。

## 2. 过流：当前工程有链路，实机验收尚缺

### 源码中的完整配置

| 文件 | 位置 | 配置 |
|---|---|---|
| PID `Core/Src/comp.c` | 第 40–46、68–74 行 | COMP1 正输入 PB1，负输入 DAC3 CH1，输出不反相，无迟滞、无消隐 |
| PID `Core/Src/tim.c` | 第 74–77 行 | COMP1 连接 TIM1 BRK，源使能，高有效 |
| 同文件 | 第 109–118 行 | 死区码 120，Break 开启、高有效、滤波码 2；Break2 关闭，自动恢复输出关闭 |
| PID `Core/Src/main.c` | 第 163–166 行 | DAC3 CH1 设 3000，并启动 DAC 与 COMP1 |
| PID `Core/Src/stm32g4xx_it.c` | 第 260、346 行起 | TIM1/COMP 中断交给 HAL；未找到应用层过流锁存回调 |

ST 的 [TIM 扩展 HAL 源码](https://github.com/STMicroelectronics/stm32g4xx-hal-driver/blob/master/Src/stm32g4xx_hal_tim_ex.c)说明并实现比较器 Break 输入路由及 BDTR 配置。硬件封波与软件故障回调是不同环节；[TIM HAL 中断处理](https://github.com/STMicroelectronics/stm32g4xx-hal-driver/blob/master/Src/stm32g4xx_hal_tim.c)还要求对应中断源使能才调用回调。仅启用 NVIC 或出现 HAL 中断处理函数，不等于应用故障已锁存。

PID 应用未找到三相电流绝对值越限停机逻辑。USER3 回调会直接调用 PWM Start（`main.c` 第 250–276 行）；禁止自动恢复输出不等于所有软件启动入口都已被故障锁定。新锁定适配层已有禁止运动和协议故障管理，但完整 FOC 接入版本仍未上板执行。

### DAC 3000 不是 3 A

按所核对原理图的标称器件，采样电阻为 5 mΩ，差分运放增益约 `11 kΩ / 1.5 kΩ = 7.333`，零电流偏置约 1.65 V。3.3 V、12 位 ADC 下，每码约为 `0.02197265625 A`，与 PID `main.c` 第 352–354 行一致。

沿用这一标称换算，比较门槛的估计为：

```text
I_trip_nominal ≈ (3000 − IC_Offset) × 0.02197265625 A
若 IC_Offset = 2048，则约为 +20.918 A。
```

这是依据源码与电路的推算，**不是实际板卡的校准值或允许电流**。DAC/ADC 误差、参考电压、放大器偏置、实际器件和 PWM 采样条件都需要核对。不能把母线电源的 3 A 限流，或 Iq 指令 ±3 A，解释为该比较器会在 3 A 封波。

PB1 对应 OP3/C 相采样输出，现有单个非反相比较器只比较该输入的上限；未发现其余相及负电流的独立比较配置。手册第 80 页画的是 Ic 到达阈值后统一封掉三相 PWM 的示意图，不能据此认定六个方向的电流都受到瞬时监视。低侧采样还受导通窗口影响，覆盖性须另验。

### 同名归档的实际差异

- `10.TIM1_OPAMP_ADC_DAC.zip` 内实际上是 `6.TIM1_OPAMP_ADC/STM32G4_TIM1_OPAMP_ADC`；它的 `Core/Src/tim.c` 第 101 行为 `TIM_BREAK_DISABLE`，主程序没有 DAC/COMP 初始化，并在初始化阶段直接开启相位 PWM。**不能把这个归档直接用于保护验证。**
- Folder 4 单独的 `main.c` 第 109–110、125–127 行确实初始化并启动 COMP1/DAC3，阈值亦为 3000；但这个孤立文件不足以证明它与上述归档组成一致的完整工程。
- 用户手册第 78–86 页给出封波机制、外设设置与波形展示，没有提供该块板子的实测触发电流、误差、封波延迟及故障恢复验收表。测试手册也未发现此类记录。

后续过流验证应分别记录门槛校准、比较器触发、TIM1 封波、六路输出安全电平、故障锁存和禁止重启；先设计无功率输出或受控低能量验证，再决定电机试验。**本次没有用堵转、短路或提高电流来触发保护。**

## 3. 参数边界：有可复用限制，没有已验证的 TD3 安全域

| 限制 | 源码依据 | 含义 |
|---|---|---|
| 默认 Kp / Ki | PID `MATLAB/FOC_Model.c` 第 38–43 行：`0.003389 / 0.00144` | 初始控制参数，没有附带增益上下限验收 |
| 速度 PI 输出 | 同文件第 483–501 行：±3 A | Iq 指令饱和；第 560–568 行有条件积分抗饱和，不能保证实际电流瞬时不超限 |
| NNSMC 叠加后输出 | 同文件第 607–609 行：再次限制 ±3 A | 当前基准包含 PI + NNSMC，应保留实际控制结构做比较 |
| d/q 电流控制器输出 | 同文件第 849–878 行：各自约 ±12.4707661 V | 各轴电压指令限制，不是母线过压/欠压故障保护 |
| 示例启动条件 | PID / 模糊 PI 的 `readme.txt`：2 对极，参考速度不能低于 1000 | 该模型的启动适用条件，不能推广为所有电机的最小速度或已验收的转速范围 |

### 模糊 PI 确实给出了增益范围

模糊 PI `Core/Src/main.c` 第 403 行设置基础增益为 `Kp_base=0.003389`、`Ki_base=0.00144`、`Kd_base=0`。`fuzzy_pid.c` 第 13–35 行的两个 7×7 规则表分别给出 `ΔKp ∈ [−0.6,0.6]`、`ΔKi ∈ [−0.5,0.5]`，第 130–132 行按 `K = K_base × (1 + ΔK)` 更新。

对有限且有效的误差输入，规则表推出：

| 参数 | 源码可达范围 |
|---|---|
| Kp | `0.0013556 ≤ Kp ≤ 0.0054224`（基础值的 0.4～1.6 倍） |
| Ki | `0.00072 ≤ Ki ≤ 0.00216`（基础值的 0.5～1.5 倍） |
| Kd | 恒为 0，因此实际是模糊 PI |

`main.c` 第 681–683 行把规则结果写回实际速度 PI。49 组规则是**成对的离散增益集合**，不等于任意 Kp/Ki 组合都在原例程中运行过。源码没有验证 NaN 输入、增益平滑变化或这一区域内所有工况的稳定性；这些范围可作为建模/比较的来源，不能直接标成已批准的 TD3 实机探索矩形。

初始化中的 `e_max=500` 和 `ec_max=1000000` 用于模糊输入归一化/截断，不是超速、加速度或过流故障阈值。

### 通用 PI 模型也有输出限幅，但数值不同

`PI_Control.zip` 的 `PI_Control/PI_Control.slx` 包含积分器与输出饱和块，使用 `OutputMax/OutputMin`。模型 XML 中，一组实例填入 ±30，另两组填入 `±24×0.9×sqrt(1/3)`（约 ±12.470766 V）。这是该独立模型的实例参数，不能把 ±30 移植为当前电机的电流限制；本次只解析 XML，未运行模型或确认其全部信号单位。

## 4. 对当前 TD3 接入的影响

1. **复用已有实现：**三相 ADC、COMP1→TIM1 Break、PI 抗饱和与最终 Iq 限幅均已有源码依据，不需要假设它们不存在。
2. **补保护证据：**现有 DAC 门槛看起来远高于 ±3 A 指令范围，且只看到 C 相上限比较；先确定该设备保护目标，再校准、验证覆盖与锁存，不能直接照搬 3000。
3. **补参数证据：**默认 PI 值、模糊规则集合和原试转记录分别保留；从中设计独立有界比较，不能把整个模糊增益范围自动批准为 TD3 的动作空间。
4. **按真实硬件处理热风险：**当前没有温度观测，保留缺失状态；后续选择测温或经过验证的替代热保护后，再实现相应接口与校验。

现有 RAM PIL 只证明计算/禁能函数与诊断端点在 MCU 上执行过，没有验证比较器真实过流响应。此次资料核对也没有改变“完整固件尚未运行、TD3 尚未接管真实电机”的状态。
