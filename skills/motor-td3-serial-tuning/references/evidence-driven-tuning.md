# 实机探索、训练时序与候选准入

用于已经接入真实遥测和原子参数回读后继续改善效果。先读取本次构建、采集、训练与停止摘要；这里的工程入口不能证明另一块板卡已通过保护或性能验收。

## 持续工作与授权

- 保留用户已经给出的设备、无温度门实验例外、探索范围、时长和发布偏好，不重复询问同一授权。用户明确允许进一步 Kp/Ki 探索时，先声明下一批具体数值、时长、间隔和停止规则，再在该授权内推进。
- 每批仍有有限预算；故障立即结束本批，不自动清故障或重启。用户报告断电、接线变化等现场变化后，重新核实相关状态。
- 总范围、单次参数步长、动作周期、运动预算和部署许可分开记录。较大总跨度通过已回读的中间参数分步实现；不能靠修改步长或保护上限实现。
- 特定用户授权的带电烧录例外，只适用于已审查的精确旧/新镜像以及复位前六路功率 GPIO 低电平核验。未知镜像和 RAM 覆盖试验不能沿用该例外。温度门规则见现有热参考文件，本文件不修改它。

## 先诊断再训练

| 观察到的问题 | 处理 |
|---|---|
| 开机阶段占了大半评价窗 | 依据 RunStage/实际时间分离启动、过渡与稳态；预先声明评价区间。保留启动完整日志和故障，不删除失败试验。 |
| 参数切换比机械响应快 | 按实际响应选择保持时长；先用固定点长保持识别收益。短窗口不能被说成独立重复试验。 |
| Hall 估速与采样相位相关 | 检查各 Hall 扇区覆盖、原始边沿和时钟。采集抖动与控制周期变更分开；边沿环仅有尾段时明确覆盖时长。 |
| Actor 近乎输出常数 | 检查动作覆盖、上一档参数与时间特征、双 Critic 对已试动作的排序、行为约束和实际动作映射。不能靠反复训练种子证明改善。 |
| Ki 没有有效探索数据 | Ki 动作掩码为 0、实际 Ki 固定；先单独采集 Ki 响应，禁止从 Kp 数据推出可下发 Ki 策略。 |

固定目标速度下把增益档位与上一档组合平衡，避免目标速度变化和增益效果混淆。先改一个参数，减少无法解释的 Kp/Ki 联合变化。更大探索点先保持“实验候选”，不能写成已验证局部域。

## 有效决策与动作坐标

一条动态决策包含：决策前实际状态与短历史 → 命令 → 实际生效时间/增益 → 后续响应 → 下一次决策前状态。保持同一增益的通信保活包不自动算成新策略决策。

按 MCU 时钟对齐；拒绝 boot 混用、序号断裂、缺少实际应用回读、响应跨增益变化、故障和不完整窗口。保存被拒原因以及原始遥测、命令和哈希。检查相邻决策的下一状态与后继状态是否衔接。

原例程在 BEGIN 前可能上报模糊 PI 初始化增益，与外部基准不同。保留这些未启用/尚无应用序号的原始数据和常规故障、时间、物理边界检查；不能当作探测参数 ACK 或训练动作，也不能仅因不在探测档位而判定运行故障。进入外部增益控制后仍严格验证实际生效值。

动作必须明确是绝对增益、相对当前增益的增量还是相对基准的归一化坐标。扩大范围后重新版本化映射、Actor 输出范围、Critic 回放动作和推理契约；不能将新范围裁剪进旧经验池。桥接步只按实际生效的桥接动作记录，不当成最终目标已执行。

决策时长不等时，奖励积分和折扣时长须相匹配。仓库的测时扩展采用 `gamma^(measured_dt/base_dt)` 和后续实测响应积分；通信应用延迟不虚构成新动作响应。该扩展是工程选择，不能描述为原生 `trainFromData` 自带的行为。保存旧奖励作为对照并注明尺度变化。

## 训练与部署状态

分 boot/物理试验划分训练与验证，冻结划分后去重。不能随机打散同一轮相邻窗口来声称独立验证。报告唯一窗口数、实际梯度更新数、种子、动作掩码、归一化/映射版本和数据 SHA-256。

检查点须保留 Actor、双 Critic、目标网络、优化器、随机数状态和回放来源。自定义测时 TD3 使用自定义恢复状态；即使另存原生 agent 供推理，也不能未经核对用原生训练入口接着训练。

明确四种证据：

1. **训练更新**：实际执行梯度更新，保存检查点；损失/Q 值不代表实机改善。
2. **旁路预测**：记录 Actor 建议，实际行为仍是已授权控制器；建议不能与后续响应拼成实际动作经验。
3. **实机性能验证**：冻结候选、关闭训练/探索，与基准在同条件下交替重复；通过目标速度和未训练工况验证。
4. **MCU 部署**：性能与既有保护门均通过后，才做 C 数值一致性、主机/ARM 编译、目标时延验证和部署。

沿用当前项目准入要求：速度 RMSE 至少降低 5%，平均峰值名义电流和峰值速度不增加，故障为 0；每轮 STOP 确认、六路关闭、核心暂停和通信释放可核验。缺少独立电流标定时称“名义电流”。未达性能/保护门，`deployment_allowed=false`、`performance_claim_allowed=false`；拒绝候选并继续基准 PI。
