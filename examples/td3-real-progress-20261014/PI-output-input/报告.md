# 实际 PI 输出输入对照与 TD3 训练

## 改了什么

原 10 维输入中，第 4 维被前一帧 Hall 误差替换，第 9 维是更早一帧误差，第 10 维是被掩码忽略的经过时间。这使 Actor/Critic 没有最近一次 1 ms PI 边界真正使用的误差，不能仅由网络原输入准确还原该边界的 Iq 指令。板端原始遥测仍有 `error_history`，先前原生成 C 的 35000 组检查已验证单精度还原公式。

新增 `history20-40-PI-command-v1` 输入对照：前九维原样保留，第十维改为最近一次 PI 指令 `float32(clamp(float32(kp*error_history + integral_output),−3,3)/3)`，并启用该输入。它是指令，不是独立实测 Iq。不同于旧输入版本，网络不能直接交给旧实时输入构造器。

## 数据与核验

使用已冻结的 42 个真实 boot、1792 个 300 ms 经验窗口：训练 899 个/21 个 boot，验证 893 个/21 个 boot。它们来自既有数据，没有新的物理试验，不能与父包相加计数。最近 v28 的新增低 Kp 数据仍未进入旧 v7 训练范围。

新输入仅改变第十维，实际动作、奖励、第一至第九维、物理键、训练/验证归属完全相同。第十维的中心与尺度只用训练 boot 的源状态和下一状态拟合；验证 boot 未参与。Python 与 MATLAB 分别从原始 PI 字段计算 3584 个输入，数值一致。实时时序输入函数又逐一复现这 3584 个训练/验证向量，最大误差为 0，拒绝旧输入版本。错源值、错下一状态序号、错来源哈希和错 split 的四类数据均在保存前拒绝。

## 模型预测对照

实际记录动作下的速度响应预测误差，相比旧输入减少约 0.3935%；名义峰值电流平方的预测误差减少约 0.0222%。预测模型的拟合、正则选择仍只使用训练 boot，保持独立验证。

这些是预测误差变化，不是速度控制性能改善。该补充输入有信息，但目前增益较小。

## TD3 确实执行了训练

保持原训练器、TD3+BC 配置、600 次双 Critic 迭代、300 次 Actor 更新及随机种子 7/17/27；总计 1800 次双 Critic 更新迭代、900 次 Actor 更新，保存三个自定义检查点。

与旧可行动作表示训练逐一核对：实际动作抽样次数、保持/切换抽样次数、目标动作噪声、boot 随机权重、价值平移及优化器设置相同。输入变化会改变 Critic 初始化系数，这是本次对照的预期效果。Actor 仍输出可行区间内的位置，Critic 使用绝对 v7 动作坐标；没有伪装为可直接续训的原生 agent。

| 种子 | 单次动作模型预测的速度 RMSE 收益 |
|---|---:|
| 7 | 0.1023% |
| 17 | 0.1138% |
| 27 | 0.1038% |

预测都没有达到 5%，模型也未校准闭环反事实不确定性。这不是固定 Actor 对比基准 PI 的实机结果，不能拿来申请性能通过。策略输出范围、原单步限制和 Ki=0.00144 掩码通过；没有向板子下发 Actor。
