## 发现的问题与修正

### CAN 收尾顺序

第一轮旧镜像完成握手和 30 组诊断，但释放 PCAN 后板端仍发送。
随后读到 IRQ 故障=1、ECR=`0x00090048`、PSR=`0x70B`（LEC=3，ACK 错误）。
这些观测与发送方失去 ACK 一致；采集窗口通过不能写成完整收尾通过。

入口改为保持适配器提供 ACK，暂停已完整核验的禁止运动核心，读取禁能/故障状态，再释放 CAN。
第二轮即使采集被拒绝，这个清理路径仍通过；最终轮也通过。
它只适用于从未启动 TIM1 的诊断镜像，不能把 CPU 暂停当运行电机的急停。

第一轮外部收尾还使用了半字 TIM1 写入，CR1/BDTR 回读有非目标位变化。
断电复位已恢复配置。当前采集器取消外设写入；单独调试 TIM1 时应使用核验过的 32 位访问并回读，
不能假设半字写保留其他位。

### HELLO 与首帧诊断的竞态

第二轮先收到 `0x622`，尚未完成握手，主机立即拒绝数据并正常清理。
代码审查发现，前台查询 HELLO 待发送状态后，SysTick 可能接受请求、设置 owner；
前台随后读到新的 owner，就会先发送原始诊断。

修正为在同一临界区查询 HELLO 并取诊断发送权限快照。
新增 C 回归检查，在该临界区释放处模拟 SysTick 接受 HELLO，要求身份回复完整后才出现原始诊断。
SpeedLoop 与旧适配层各 **26 项**检查通过。重新编译、断电烧录后，最终 3 秒复测通过。
采集器继续拒绝握手前诊断，没有忽略未验证数据来掩盖问题。

### 下载前复位暂停

首次更新下载中 Flash 算法发生 HardFault：PC=`0xFFFFFFFE`、IPSR=3、CFSR=1、
HFSR=`0x40000000`；SysTick CTRL 仍为 `0x10007`。
暂停核心没有清除启用的计时器/中断，这些状态与擦写期间异常跳转相符。

保持 24V 断开，执行 reset halt，确认 SysTick CTRL 和 TIM1 寄存器清零后重试。
下载成功、32832B 全量比较一致后才运行诊断。流程已更新，没有直接恢复未知 Flash。

## Codex 的作用与结论

Codex 编写有界采集入口，核对固件和身份，分析电压、ADC 新鲜度、静止转速与故障，
修正竞态和收尾问题，重新编译烧录，并整理真实结果。主机采集检查 **9 项**通过，已加入 CI。

本次打通 **真实 MCU → CAN → Codex 管理的日志和结果分析**。
四个原始帧不是原子快照，没有动作应用时间/序号；温度缺失，电流比例未独立标定，保护尚未验收。
所以 TD3 经验为 **0**，没有用静态数据训练，也没有把 Actor 写入本次 Flash。
此前 Actor RAM PIL 和 mock 性能比较仍是单独证据。
