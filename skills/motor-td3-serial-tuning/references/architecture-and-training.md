# 本地训练架构与学习契约

## 串口数据怎样用于训练

```text
STM32 电机控制器（现有 FOC、电流环、速度 PI、独立保护）
        ⇅ 版本化串口协议、应用确认、真实参数回读
串口监督器（唯一端口所有者；独立安全检查与动作租约）
        ├── 原始帧、状态、动作与故障日志
        ├── 策略执行副本 → 有界候选参数 → 设备确认
        └── 有效经验队列 → TD3 训练进程 → 候选检查点
                                            ↓
                                     旁路/独立评估

Codex：配置这些程序，检查摘要、曲线与停止原因，修改代码和训练设置。
```

电机继续由 MCU 上的闭环控制；电脑调整速度 PI 参数。聊天响应的延迟和不固定的工具调用节奏不进入控制时序。

梯度训练不能阻塞串口监控。监督器若仍在运行但训练器失去进展，只在预先定义的有限租约内维持已验证动作，超时停机；不能因为心跳线程还活着无限延长运动。检查点不能未经评估直接热替换当前策略。队列只保留最新且未过期的动作，禁止按顺序执行一批已经过期的参数。

## 先定学习任务

### 动态速度 PI 参数策略（默认）

每个回合包含多次参数决策，网络根据当前状态选参数。状态包括经尺度化的：速度给定、速度反馈、速度误差及短历史、PI 积分输出、实测 q 轴电流/可解释的电流测量、母线电压、实际 Kp/Ki；根据通信延迟加入时间间隔与动作历史。

负载转矩没有实际传感器时不能假装是测量输入。仅有三相电流时，采用可验证的电流特征，并记录其定义；估计量须标明来源。不能将局部变量存在等同于固件真正上报了该量。

网络连续动作在 [-1, 1] 内，经确定映射成为已验证局部范围内的 Kp/Ki。映射、参数变化限制和设备实际采用值都记录。裁剪、拒绝、基准接管不能被误记成原始网络动作已执行。若采用安全投影，明确其作为环境一部分的数学含义，并保持 actor、critic 和回放动作坐标一致；审计器默认将干预步排除出普通学习输入。

### 每轮固定参数

回合开始选一组 Kp/Ki，在整个试验中保持不变，结果汇总成一个奖励。这更接近单步参数优化。可以保留此模式，但不能把两种模式混合进未区分任务定义的经验池。若用户只想找一组固定最优参数，说明贝叶斯优化等方法可能更省实验次数。

## 一条有效经验

TD3 需要 `(状态, 已生效动作, 奖励, 下一状态, 终止标志)`。可用的实际采集步骤：

1. 在设备时间 `t0` 获取完整状态和当前参数；记录采样序号。
2. 产生候选，监督器检查边界、故障、数据新鲜度和租约。
3. 发送带命令序号的原子参数事务；设备在控制周期边界应用后回报实际参数与 `t_apply`。
4. 从应用时刻之后开始统计该动作的响应，在固定决策时间窗末得到下一状态及奖励；用 MCU 时间，不以串口到达主机的顺序替代。
5. 检查这一窗里没有别的参数写入、复位、不可解释的丢帧或模式切换，再进入学习队列。

通信延迟期间的旧参数响应不能算成新动作效果。时钟复位、帧重新排序、未收到应用确认或未知终点时记录诊断，禁止虚构下一状态。扩大时间窗或加入历史只能缓解时延问题，仍需检查任务是否充分可观测。

状态归一化使用固定物理尺度或可版本化的归一化器；保存随模型交付，评估时冻结。缺失电流、故障码等字段不能用零填充冒充正常数据。

## 奖励与终止

用已归一化量计算奖励，例如速度误差、过冲、电流占用、参数变化和饱和持续时间的加权惩罚。给定转速变化要与异常过冲区分。按整个响应窗统计电流峰值和误差，不能只拿最后一点证明安全。当前实现使用跟踪误差、电流均方值、峰值电流、过冲和饱和比例的组合奖励，并把这些分项写入经验指标，便于 Codex 分析候选是否以更大电流换取更小误差。

工程保护是硬约束；奖励里加大扣分不能取代停机。安全终止只在实际动作和下一状态可确认时形成带故障惩罚的终止经验，否则仅作事件日志。普通回合时间上限使用 `truncated`，可确认的安全故障使用 `terminated`；失联和未知末状态不送入普通 TD3 的 bootstrap 目标。

训练分数增加不能证明优于原控制器。评估要固定探索关闭、工况与初态、实验预算和评价尺度，检查误差、超调、恢复时间、电流峰值、饱和比例、故障/干预次数和最差工况；保留随机种子和失败结果。

## 实机在线学习

用户可以选择从实机串口交互直接训练。先由已验证控制器建立可重复基准，只在已验证的局部增益域内生成小幅探索。转速给定和负载试验计划预先限定；网络不能自行提高电流限幅、转速上限、保护阈值或重新解锁故障。

优先使用仿真预训练减少实机试错，但已有授权的实机在线学习不被替换成用户未选择的其他任务。动作周期由电机动力学、串口带宽、确认时延和保护响应验证决定；不要将“10 ms”写成通用安全周期。保护执行比调参周期快且独立。

Stable-Baselines3 的默认学习预热可能随机采样整个动作空间。实机不要直接调用带默认随机预热的 `learn()`；定制收集器，使用已验证基准附近的行为策略，并确认回放池记录的是实际执行动作。

训练时可以维护新策略候选，实验执行只使用当前获准策略。只要不破坏经验定义，同一当前策略可持续收集数据并供 TD3 更新；会话内策略发布频率、最大改动和回退条件必须明确。

## 已有日志与旁路模式

旁路网络预测没有作用于电机，不能把预测参数与电机随后响应拼成因果经验。仍可保留实际基准动作形成有标识的数据，但单一动作附近数据通常不足以学习广泛的参数策略。

普通 TD3 的离策略回放适合重复利用已采集的交互经验；它不保证从一份固定、覆盖不足的日志训练出有效策略。纯离线训练需要分析动作覆盖与分布偏移，可考虑带行为约束的离线方法或用于仿真模型辨识。用户仍要求 TD3 时如实报告此局限，不把网络在未尝试动作上的 Q 值当成验证。

本仓库的 mock 训练使用局部增益步长，因此独立零均值动作噪声会造成“基准附近随机游走”。模拟对象增加了有界的方向性覆盖轨迹，使 Kp/Ki 能到达已验证矩形的四个方向；这是模拟数据收集策略，不能原样用于真实电机。真实串口仍使用小幅噪声，方向性探索必须由目标电机、负载和保护验证后单独授权。模拟训练在回放达到 128 条后增加批量更新，实机保留较保守更新频率。EMTD3 的随机 Actor 暖启动和随机负载扰动可作为后续对照，但必须在未参与训练的工况上检查跟踪、电流和安全干预，不能因为论文中的探索策略就放宽硬件保护。

PPO 的部署形态与 TD3 相同：只部署确定的 Actor 均值推理，策略方差、Critic 和训练器留在主机。PPO 是 on-policy，适合在仿真中用较新数据稳定更新，但会消耗更多交互样本；TD3 的双 Critic 和离策略回放更适合复用受限的连续动作经验。两者应在冻结的未参与训练工况上比较，不能仅按算法名称选择。

## 实现路线

已接入 SpeedLoop 工程的持续采集、自定义测时训练和候选准入见 [evidence-driven-tuning.md](evidence-driven-tuning.md)。下面的通用 TCP/mock 路线与后续特定工程实验分别记录能力；原生 `trainFromData` 的固定折扣和自定义测时 TD3 不混用恢复接口。

本包使用 MATLAB Reinforcement Learning Toolbox 的 `rlTD3Agent`，按实际安装版本核对接口。Python 监督器通过 pyserial 占用串口；MATLAB 通过认证的本机 TCP 请求状态和动作窗口。MCU 参考协议和保护见 [firmware-integration.md](firmware-integration.md)。

本包已包含监督器、CRC 串口适配器、状态/奖励模块、真实 MATLAB TD3 训练、固定策略评估、小型 Actor C 导出与 mock/MCU 主机测试；操作见 [matlab-runtime.md](matlab-runtime.md)。默认入口只运行 mock。MCU 快速保护独立执行，梯度更新安排在已确认禁能的回合间；候选策略在实机不会自动接管。特定工程的 HAL、参数写入点、无扰切换与烧录流程仍需实际接入和验证。
